### Packages created in S0

The seven packages S1 needs, as skeletons with no behavior: `core`, `interactions`, `react`, `react-ui`, `styles`, `temporal`, `testing`. Each gets its `AGENTS.md` and `CLAUDE.md`, Nx tags for its layer, coverage thresholds, size budgets and `sideEffects`. The P5 reference types go into `core`, `interactions`, `react` and `react-ui` as `.type.ts` files; the functions they declare (`createCalendar`, `defineMachine`, `useCalendar`, …) are implemented by the slices that need them. "CI green on an empty workspace" then means packages with types and no behavior.

### Build

Vite 8 library mode for every package (ESM only, `build.target: 'es2025'`, one entry per public entry point, dependencies external), with `tsc --build` emitting the declarations. The React packages add the React Compiler through `@vitejs/plugin-react`. Vite also handles `react-ui`'s CSS Modules (D-69) and the second `styles` build. S0 proves the output: a test fails if any built file contains syntax newer than ES2025.

### Lint and boundaries

- **Nx tags** per layer (`layer:kernel`, `layer:machines`, `layer:binding`, `layer:ui`, `layer:styles`, `layer:module`, `layer:loader`, `layer:testing`, `layer:tooling`) with `@nx/enforce-module-boundaries` enforcing the [dependency direction](../architecture.md#package-map).
- **typescript-eslint** strict, type-checked.
- **D-46 rules** as local ESLint rules in `tools/eslint-rules/`: the file suffixes, function declarations for named functions, a single object parameter for functions with more than one argument, `displayName` on components.
- **Layer rules:** the binding may not use timers, `focus()`, keyboard event handling or hit-testing APIs; `react-ui` may not hold behavior logic (no handlers except those from getters, no timers, no state beyond slot composition). Both are `no-restricted-syntax` and `no-restricted-globals` rules, so they need no new dependency.
- **TSDoc** on every exported symbol (`eslint-plugin-tsdoc`, plus a local rule that an export has a doc comment).
- **The React Compiler rules** from `eslint-plugin-react-hooks` on the React packages.
- **Failing fixtures** in `tools/fixtures/` prove each rule: a kernel file importing React, `core` importing `interactions`, the binding calling `setTimeout`, an over-budget entry point, a binding over 600 lines, a missing TSDoc. A test runs lint and the size checks on them and expects each to fail with its rule.

### Tests

- Vitest projects per package. Kernel, machine and module packages run in Node. The binding and UI run in Vitest browser mode (Playwright, Chromium, Firefox, WebKit). No jsdom (D-42).
- Coverage thresholds per package from [testing](../../standards/testing.md#coverage-d-42).
- The Playwright suite (end to end, visual, axe) is configured for three engines, each run twice: as is, and with `globalThis.Temporal` deleted by an init script (D-87). It has one smoke test against the Storybook shell until S1 adds real ones.

### Size and binding budgets

- `tools/size` builds each public entry point with esbuild (minified, gzipped), as `prototypes/p4-bench/size/measure.mjs` does, and fails above the budget in that package's `package.json` (`"bigCalendar": { "sizeBudgets": { ".": "1 KB" } }`). Budgets in S0 are placeholders for empty entry points; each slice sets the real ones.
- The binding line count: source lines in `packages/react/src`, excluding types (`*.type.ts`), tests and comments, fail above 600.
- The tree-shaking test (D-63): an esbuild bundle that imports one named export from each package, which must contain nothing else.

### Benchmark harness

`tools/bench` ports `prototypes/p4-bench/` as [testing](../../standards/testing.md#benchmarks-d-44-d-92) describes: the profiles, cold run plus warm-up plus median of 10, JSON output, the back-to-back comparison against `main`, and the PR comment table. S0 has no kernel to time, so it runs one trivial scenario to prove the plumbing; S1 adds month and week.

### Storybook shell

`apps/docs`: Storybook 10 with `@storybook/react-vite`, an introduction page, the TypeDoc-to-MDX step wired for the packages (empty until they export documented symbols), and the writing standard's page structure (tutorial, how-to, reference, explanation; D-64). Deployed to GitHub Pages on merge to `main` (D-48).

### CI (D-48)

GitHub Actions, in new workflow files. The attempt-1 files are deleted in task 1. Attempt 1's `docs.yml` and `release.yml` were disabled in GitHub on 2026-11-02, and that state stays with those paths, so the new files use other names.

| Workflow      | When             | Runs                                                                                                                                                                                        |
| ------------- | ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `pr.yml`      | pull request     | affected lint, typecheck, unit tests with coverage, build, boundaries, sizes and the binding count, tree-shaking, type checks, commitlint, the decision-entry check                         |
| `browser.yml` | pull request     | the Playwright suite on three engines, twice each                                                                                                                                           |
| `bench.yml`   | pull request     | the benchmark harness against `main`; posts the table                                                                                                                                       |
| `smoke.yml`   | pull request     | the bundler and runner smoke tests: Vite, Rollup, esbuild, webpack, Rspack, Next.js (Turbopack and webpack), Vitest, Jest (ESM, and CommonJS with `--experimental-vm-modules`), `node:test` |
| `pages.yml`   | push to `main`   | builds and deploys Storybook to GitHub Pages                                                                                                                                                |
| `release.yml` | never, until 1.0 | not created; Nx Release is configured in `nx.json` and runs only locally with`--dry-run`                                                                                                    |

- **The decision-entry check** (agent toolset): a pull request that changes `docs/spec/` or an existing row of `docs/decisions.md` must also add a new `D-NN` row; editing or removing a past row fails.
- **Never Nx Cloud.** CI runs affected tasks with the local cache, and `nx.json` sets `neverConnectToCloud: true` so Nx never offers to connect.
- The smoke tests add their bundlers and runners as dev dependencies of `tools/smoke/*` only: Rollup, webpack, Rspack, Next.js and Jest, at the versions in the [support matrix](../support-matrix.md) or newer.
